## 3. 必须直说的：模型现在还打不出和牌

跑 `play_model.py --games 2` 的真实输出：

```
loaded checkpoints/riichi_net.pt  arch=convformer_v1  iters=3
game 0 seed=1000: 流局  点数差=[0, 0, 0, 0]
game 1 seed=1001: 流局  点数差=[0, 0, 0, 0]
共 2 局：和了 0，流局 2
```

**这不是 bug，是当前训练量的真实水平。** 我做了排查，结论如下。

### 3.1 排查过程（全部实测）

| 检查项 | 结果 | 判定 |
| --- | --- | --- |
| 引擎牌数守恒 | 200 局 0 违规 | ✅ 引擎正确 |
| 引擎和了合法性 | 强制和了 14 例全过 | ✅ 引擎正确 |
| 点数守恒 | 200 局 0 违规 | ✅ 引擎正确 |
| 单局摸牌数 | 平均 **71.5** 张（真实麻将 18 巡 × 4 = 72） | ✅ 引擎正确 |
| 牌墙消耗 | 发牌后 82 张，与公式一致 | ✅ 引擎正确 |
| 起手刻子分布 | 800 手牌中 726 无刻子 | ✅ 符合真实 |
| 14 张时 `_is_tenpai` | 60 次检查 0 次听牌 | ✅ **正确**（14 张本就不该「听牌」） |

### 3.2 真正的瓶颈

在 1955 次「14 张手牌」决策点上，统计「打哪张能达到听牌」：

```
best-waits 直方图: {0: 1943, 1: 6, 2: 3, 3: 2, 8: 1}
```

**1943/1955 = 99.4% 的时刻，无论打哪张都是 0 待牌。**

原因：麻将一局每人只摸约 18 张牌，且每次摸牌前手牌是 14 张（含刚摸的），
要让「打掉一张后进入听牌」需要手牌已经接近成型。
随机策略下这个条件极少成立。

**这是真实的麻将难度，不是引擎缺陷。** 参考项目也一样——
它们的纯血线跑 32–64M 局才到 share 0.4568，同样以「大量流局」为常态。

### 3.3 训练信号的问题

```
iter 0 games=2 win=0 draw=2 pol=-0.0000 ent=3.988 R̄=+0.000
iter 2 games=6 win=0 draw=6 pol=-0.0000 ent=3.989 R̄=+0.000
```

奖励均值恒为 0 → **策略梯度恒为 0** → 网络学不到任何东西。
熵 3.988（接近 log(54)=4.0）说明输出还是均匀分布。

**所以当前 checkpoint 是一个「结构正确但未学到信号」的模型。**

## 4. 为什么奖励是 0：流局罚符也没生效

引擎实现了流局时的听牌罚符（供託），但因为
「能听牌的时刻」几乎不存在，罚符也几乎不触发。

对照：真实麻将一局约 40–50% 和牌率；我们这里 2/200 = 1%。
