# 额外任务 + 完成奖励（2026-11-05）

> 用户要求：「每个模型都给额外任务：额外任务完成也有奖励」。
> 落地：新增 `mahjong/aux_tasks.py`，每局给**每个参赛者/模型**发一份任务清单，
> 完成即得奖励点数；arena 排名（Elo）与训练 reward 都接同一套判定。
> 读数：600 局竞技场已把奖励计入 Elo；`bc_v1` 完成任务最多（+580/局），
> 纯神经模型普遍只拿到基础分（+198~+248），立直/和牌类任务几乎为 0。

## 1. 任务清单（奖励点数）

| 任务 | 奖励 | 判定 |
|---|---|---|
| `win` 和牌 | +1000 | 本局和牌 |
| `tsumo` 自摸 | +300 | 自摸和了 |
| `mangan` 满贯+ | +500 | 和牌且 ≥5 番 |
| `riichi` 立直 | +300 | 本局宣告过立直 |
| `no_dealin` 未放铳 | +200 | 本局没有放铳（流局也算完成） |
| `tenpai_draw` 流局听牌 | +200 | 荒牌流局时处于听牌 |
| `fast_tenpai` 8 巡内进听 | +300 | 需轨迹：逐决策观察，前 8 摸内进听 |

实现上分两类：
- **局末可判**（`static_tasks`）：前 6 个，直接从 `GameResult` + 手牌状态判定；
- **需轨迹**（`AuxTaskTracker.observe`）：`fast_tenpai`，在每个 `env.step` 后观察。

## 2. 接入点

### 竞技场（arena_elo.py）——「每个模型」都发任务

```python
trackers = [AUX.AuxTaskTracker(i) for i in range(4)]   # 每局 4 家各一份
while r is None:
    for tr in trackers: tr.observe(env)                # 轨迹任务
    ... env.step(acts)
for tr in trackers:
    done, bonus = tr.finish(env, r)                    # 结算任务奖励
```

排名口径：`elo_update(..., [净点数 + aux_weight × 任务奖励])`——**完成奖励真的计入
Elo**（`--aux-weight`，默认 1.0，可设 0 关闭）。ELO.md 增加「任务奖励/局」列
和「额外任务完成率」表；`rules/ELO.json` 同步保存 `avg_bonus`/`aux_tasks`。

### 训练（train_hanchan.py）——奖励整形

新增 `--aux-bonus-weight`（默认 0=关闭）：开启后每局终局 reward 加
`aux_bonus_weight × 任务奖励 / 1000`，让模型在追点之外也追任务完成。
（下一个训练周期可开 `--aux-bonus-weight 0.3` 对照。）

（`arena_elo.py --games 600 --seed 0 --aux-weight 1.0`，14 参赛、每人 158–188 局）

| 9–14 | 其余模型/基线 | 1357–1467 | 0–0.6% | −983…−240 | +204…+248 |

**任务完成率亮点**（见 `rules/ELO.md` 附表）：

- `bc_v1`：win 17.9% / mangan 9.5% / riichi 35.1% —— 任务奖励最高 +580/局；
- `greedy_tenpai`：riichi 41.3% / tenpai_draw 26.7%，奖励 +506；
- `damaten(默听)`：riichi **0%**、tsumo 6.2%（默听自摸多）、奖励 +396；
- 纯神经模型（riichi_net / from_games / a2c / dagger / hc）：win 0–0.6%、
  `fast_tenpai` 0–0.6%，基本只拿 `no_dealin` 基础分（+198~+248）——
  **额外任务完成了对「模型到底会不会打」的额外区分**。
- Elo 名次与无奖励时一致：任务奖励与净点数高度相关（和牌者同时拿点数与
  win/tsumo/mangan 奖励），没有出现「靠任务奖励翻盘」的案例。
