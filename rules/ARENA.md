# 竞技场设计：策略怎么产生，怎么判定排名可信

> 交付物 2/4 · 竞技场设计
> 对应实现（规划中）：`riichi-rl/arena/`、`riichi-rl/eval/`
> 规则地基见 [RULES.md](RULES.md)，场地表示见 [STATE_REPRESENTATION.md](STATE_REPRESENTATION.md)

---

## 0. 先说结论（不想读全文就看这段）

1. **策略来源：独立训练 + 奖励维度正交设计**，不是「一个训练过程存多个 checkpoint」。
   理由在 §1。
2. **模拟器从第一行就写成 4 agent 混战**，每一步返回 4 个主体的状态，
   而不是「当前行动者是谁」。这是竞技场能成立的前提。
3. **排名判据用配对差值 + 座位轮换**，并给出「看起来赢但不可信」的具体情形和判别法（§3.4）。
4. **同种子对照：不采用**，明确放弃并给出理由（§4）。这是最容易骗自己的地方。

## 1. 策略怎么产生

### 1.1 三种候选做法

| 方案 | 做法 | 能回答什么 | 答不了什么 |
| --- | --- | --- | --- |
| A. 单训练多 checkpoint | 一个 PPO 训练过程，存不同步数的权重 | 「学习曲线上哪一步最强」 | 策略之间的**相克关系**；不同奖励导致的行为差异 |
| B. 独立训练，奖励不同 | 每个策略独立训练，奖励函数不同 | 「奖励设计如何塑造打法」、策略间相克 | 单调性：不同训练预算带来的混淆 |
| C. 人工风格指定 | 预先指定「激进/保守/纯和了率」 | 作为**对照组**，检验「RL 学到的 > 人工先验」 | 不能证明 RL 有效，只能做 sanity check |

### 1.2 本项目选择：**B 为主 + A 为辅 + C 做基线**

**主方案 B：奖励正交轴 × 独立训练。**

奖励维度（每条轴独立取一个设定，其余固定）：

| 轴 | 设定 | 预期长出的行为（假设，非结论） |
| --- | --- | --- |
| 目标 | R1 和了 +1 / 流局 0 | 极度追求和了率，可能无视点数 |
| 目标 | R2 点数差 ±k（k=1） | 追求点数最大化，倾向高风险高回报 |
| 目标 | R3 点数差 ±k（k=10000） | 与 R2 数值不同但形状相同，用于检验尺度不变性 |
| 目标 | R4 相对分位（只在 4 人里排名，不看绝对点数） | 抑制「囤积点数换安全」，可能长出针对性强打法 |
| 探索 | ε1 均匀随机动作 | 基线，最下界 |
| 探索 | ε2 温度 0.5 采样 | 中等随机性 |
| 探索 | ε3 温度 0.05 采样 | 接近确定性 |
| 结构 | S1 共享 trunk，4 个 head | 共享表征，可能更快收敛 |
| 结构 | S2 4 个完全独立网络 | 排除共享带来的优势，验证「独立训练」 |

**辅助 A**：每个训练过程在若干步数存 checkpoint，用于观察
「同一个奖励下的学习曲线是不是单调变强」——这是**内部一致性**证据，
不能单独用来排名（见 §3.4）。

**基线 C**：人工风格策略**只允许**由「合法动作的固定优先级」构成，
例如「优先和了 > 优先声明流局 > 优先打幺九 > 其余按编码序」。
这不是牌效表（不涉及任何牌与牌的相关性知识），
只是给 RL 一个「显然很差」的下界。若 RL 打不过它，说明有问题。

### 1.3 为什么不能只做 A

A 的 checkpoint 共享同一奖励和同一探索轨迹，本质是**同一个函数的学习过程切片**。
它们之间的强弱差异会被「训练时间」混淆，而且**不能回答相克关系**——
因为相克关系要求两个策略在**不同的奖励下**独立演化后再对打。

用户关心的「A 打 B 多少胜率、B 打 A 多少」必须用 B。

### 1.4 相克关系为什么必然不对称

即使两个策略完全相同，只要它们**在同一局里坐在不同座位**，
其表现也不同（庄家点数结构不同、摸牌顺序不同）。
所以 A vs B 的胜率**不是单一数字**，而是一个 4×4 的矩阵
（策略 × 座位），必须按座位分解后看。这一条在 §3.2 展开。

## 2. 模拟器为什么必须是多 agent 原生

### 2.1 接口约定（现在就定死）

环境的每次交互返回**四个主体的观测**，而不是一个：

```
step(action_tuple) -> (obs[0..3], mask[0..3], reward[0..3], done, info)
```

其中 `action_tuple` 是本步**所有需要决策的主体**的动作。
- 自摸打牌阶段：只有 1 个主体动作，其余 3 个是 `None`。
- 响应阶段：最多 3 个主体可能同时有动作（吃碰杠和/流局）。
- 所有主体的动作**同时**从各自的合法集合中抽取（互相不可见），
  然后按规则优先级裁决（见 RULES.md §5.2）。

这意味着模拟器内部**不存在「当前玩家」这个全局概念**，
只有「本步待决主体集合」。这是多 agent 竞技场的前提。

### 2.2 动作冲突的处理

同一张弃牌可能被多家吃/碰。裁决规则（RULES.md §5.2）：

- `RON` 优先级最高，多家和了时**逆时针离弃牌者最近者**成立。
- 吃/碰/杠之间按 吃 < 杠 < 碰 的优先级，先成立者占用，
  其余家的对应动作自动作废（环境把它们标记为 rejected，不惩罚）。

**关键**：环境必须保证「一个动作要么成立要么被拒绝」，
不能出现「两家都碰了同一张牌」。自测会检查这点。

### 2.3 混战的接口一致性

一个策略 `pi` 就是一个函数 `pi(obs, mask) -> action`。
竞技场把 4 个不同策略的对象塞进同一局，引擎不关心它们是否同源。
这让「4 个相同策略自我对战」和「4 个不同策略混战」走**同一条代码路径**，
不会出现只在某种配置下才暴露的 bug。

## 3. 竞技判据：排名要能被证伪

### 3.1 用什么指标排名

**主指标：平均点数差（average point differential）。**

理由：麻将不是零和胜负游戏，有「点数差」才能同时反映
「和得多」和「收得多」。单纯的和了率会奖励「每局都和 1000 点」
而不惩罚「三次放铳 8000 点」。

**辅助指标（都要报，因为它们会互相矛盾）：**

| 指标 | 定义 | 作用 |
| --- | --- | --- |
| 主 | 平均点数差 / 局 | 综合实力 |
| 和了率 | 和了局数 / 总局数 | 进攻性 |
| 放铳率 | 放铳局数 / 非和了局数 | 防守质量 |
| 立直率 | 立直局数 / 可立直局数 | 风格 |
| 平均和了点数 | 和了时的平均收点 | 高番倾向 |
| 平均流局率 | | 稳健性 |

**「和了率高但平均点数差低」是一个有意义的发现，不该被抹平。**
所以竞技场不合成单一分数，而是**报一张指标表 + 一个主指标排序**。

### 3.2 公平性：座位轮换是必须的

同一局里 4 个座位的信息量和点数结构不同。若不轮换，
「策略 A 赢」可能只是「A 坐庄多」。

**强制轮换协议：**

每一「批次」（batch）内，同一策略组合必须覆盖全部 4 个座次配置。
最小可行批次：4 局，把策略 A 依次放在座位 0/1/2/3，
策略 B/C/D 随之轮换。这保证在**任意 4 局**内，每个策略
坐庄次数差 <= 1。

**具体实现**：`eval/seating.py` 里按 `batch_index % 4` 旋转
策略到座位的映射。用固定种子保证可复现。

### 3.3 多少局才有统计意义

这是必须给出**数字和公式**的地方，不能说「多打点」。

设我们要检验的量是「策略 A 与策略 B 的平均点数差」。
单局点数差 `D` 的标准差在麻将里约 `σ ≈ 6000` 点（经验值，
本项目第一轮会实测替换）。

用**配对差值**（同一局里 A 与 B 的点数差之差）做检验，
方差会显著低于独立样本，因为座位与牌河被消掉了。

配对样本量需求（近似正态）：

| 想检出的真实差异 | 需要的局数（单策略对打，σ_paired ≈ 2000） |
| --- | --- |
| 500 点 | ~250 |
| 1000 点 | ~60 |
| 2000 点 | ~15 |

**本项目的判据定为：**
- 任何「A 强于 B」的结论，必须在 **≥ 400 局**上成立，
  且 **95% 置信区间的下界 > 0**（配对 t 检验）。
- 若置信区间跨过 0，结论必须写成「**无法区分**」，不写成「A ≈ B」
  也不写成「A 略强」。
- 若差异存在但置信区间下界 < 500 点，写成「差异存在但小于 500 点」。

### 3.4 「看起来赢但其实不可信」的三种情形 + 判别法

这是本节最重要的部分。

**情形一：座位偏差。**
A 在某批次里坐庄 60% 的局，于是平均点数差高 800 点。
- **判别法**：把结果按座位分解。若 A 在座位 1/2/3（子家）上
  依然领先，才算真强。若只在庄家领先，是坐庄运气。
- **可证伪断言**：把座位固定不变再打一批，优势应消失。

**情形二：共同随机数导致的虚假相关。**
若 A 和 B 在同一批次里**总是**遇到同一批牌河（见 §4），
那么两者的点数差是强相关的，置信区间会被**严重低估**。
- **判别法**：比较配对方差与独立方差。若配对方差异常小，
  说明共用了随机性，置信区间不可信。
- **可证伪断言**：改用完全独立的牌河后，置信区间应变宽。

**情形三：训练噪声当成了策略差异。**
两个策略各训练一次，偶然一个运气好。
- **判别法**：每个策略**至少 3 个独立训练种子**，
  先在策略内部求均值与方差（种子间方差 = 训练噪声），
  再比较策略均值。**若策略间差异 < 种子间标准差，则判为不可区分。**
- **可证伪断言**：换训练种子重跑，排名应稳定。排名翻转 = 噪声。

### 3.5 一句话总结判据

> **「A 强于 B」这个结论是可证伪的：把座位固定、把随机性拆开、
> 换训练种子重跑，结论必须不变。任一条不成立，结论作废。**

## 4. 同种子对照：明确放弃

用户提示里提到的风险点确实存在，这里给出决定和理由。

### 4.1 问题

若让 A 和 B 在「同一局牌山、同一种子」下对战：
- 一旦 A 打出不同的牌，B 之后看到的牌河就不同；
- B 的摸牌时序可能错位；
- 于是「同一局」在两策略分歧后就变成了**两个不同的世界**。

结果：所谓「同种子对照」只在分歧发生前有效，分歧后就是普通独立对局，
还额外引入了一个**虚假的「公平」感**。

### 4.2 决定

**不做同种子对照。** 改为：

- **共享种子池**：一批评估局用一组固定的种子集合，
  4 个策略在这批局里各自完整打一局（**同一局内 4 个不同策略混战**）。
  这样「同种子」发生在**批次层面**（同样的初始局面被反复使用），
  而不是「同种子串行重放」。
- 批次内的局面是相关的，但**批次之间独立**。
  因此统计检验以**批次**为独立单元（cluster-robust 标准误），
  而不是以单局为独立单元。

### 4.3 这样做的代价（诚实说明）

批次内相关的局面会**降低有效样本量**。
若一个批次 4 局，则有效独立单元数 ≈ 总局数 / 4。
所以 §3.3 的「≥ 400 局」实际需要更多局数来补这个损失。
这一点必须在报告里写明，不能拿「打了 400 局」就宣称有 400 的有效样本。

## 5. 竞技场的输出格式

每次评估产出一张表：

| 策略 | 平均点数差 | 和了率 | 放铳率 | 立直率 | 流局率 | 座位分布 |
| --- | --- | --- | --- | --- | --- | --- |
| rand | ... | ... | ... | ... | ... | 均匀 |
| R1-win | ... | ... | ... | ... | ... | 均匀 |
| R2-point | ... | ... | ... | ... | ... | 均匀 |

外加一张 **4×4 相克矩阵**（行 = 策略，列 = 策略，格子 = 两者对局时
行策略的平均点数差）。

**相克矩阵是本项目的核心产出**，因为单看排序看不出
「A 克制 B 但被 C 克制」这种非传递结构。

## 6. 与「纯 RL」铁律的关系

竞技场不引入任何人类知识：
- 基线 C 的「人工风格」只是**合法动作的固定优先级**，
  不含任何牌与牌的相关性判断，因此不是牌效表。
- 所有排名指标都是**从对局结果统计出来的**，
  没有「理想值」「理论最强」这类先验。
- 判据（§3）只用**统计检验**，不预设谁该赢。

若某策略「打不过基线 C」，结论是「训练失败或判据有问题」，
不是「把基线调弱一点」——后者就是把人类知识喂进去了。
