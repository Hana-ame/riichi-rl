## 0. 声明：这份规范的可信度边界（先读这里）

### 0.1 规则来源与「无法外部核验」的事实

本规范按**日本竞技麻将（riichi competitive mahjong）主流规则**写成。

**但是**：本次写作时，沙箱内无法访问任何规则权威站点做交叉核对：

| 尝试的来源 | 结果 |
| --- | --- |
| en.wikipedia.org/wiki/Mahjong_scoring | DNS 解析到非公网 IP，抓取被拒 |
| riichi.wiki（社区最完整规则库） | HTTP 403，Cloudflare 人机验证拦截 |
| raw.githubusercontent.com（多个开源记分器实现） | fetch failed |
| DuckDuckGo / Google | DNS 解析到非公网 IP，抓取被拒 |

因此：**本文档的每一条规则要么是「规则体系的共识性写法」，要么明确标注为
「本次自行决断」**（§17 假设清单）。

我**不会**把「我印象里是这样」写成确定事实。凡是无法从规则体系结构上
推出来的选择，都放进 §17。

### 0.2 本规范与「麻将常识」的边界（对应铁律 2）

RL 从零学，**引擎里不允许出现任何「人类该这么打」的先验**。

| 允许（规则层，必须有） | 禁止（策略层，绝不写） |
| --- | --- |
| 「四暗刻必须是门前状态」这类规则约束 | 听牌 / 和牌率 / 期望值牌表 |
| 「立直后只能摸打」这类动作约束 | 「打 1 字牌危险」之类的危险度权重 |
| 「宝牌数 = 剩余牌中 N 之上的个数」这类算分定义 | 副露取舍建议、门前/副露优劣权重 |
| 合法动作枚举（用于约束动作空间） | **把合法性之外的偏好写进任何统计量** |

可检验的判据：**把引擎里所有「和牌 / 番 / 符」相关的函数抽出来，
它能回答「这个动作合不合法、和了值多少点」，但回答不了「这个动作好不好」。**

## 1. 牌种与牌山

### 1.1 牌张

136 张 = 34 种 × 4 副。

- **数牌**：万 1-9、筒 1-9、索 1-9，各 9 种
- **字牌**：东南西北白发中，7 种

内部编码（本实现采用，两层索引）：

```
tile_id 属于 [0, 34)
  0-8   : 万 1-9      (m1..m9)
  9-17  : 筒 1-9      (p1..p9)
  18-26 : 索 1-9      (s1..s9)
  27-30 : 东南西北      (E S W N)
  31-33 : 白发中        (Haku Hatsu Chun)
```

### 1.2 赤牌（aka）

**本规范：仅 1m 3p 5s 各 1 张为红色，共 3 张赤牌**（§17-A2 自决项）。
红色牌**在数值上与普通同种牌完全等价**，只是计数与表示不同：物理上它仍是那张
1m 牌。引擎用独立的赤牌计数表管理，观测里单独给一位标志。

### 1.3 牌山

标准牌山 136 张，去掉配牌后剩 **94 张**。
本规范**采用死牌山（waribashi）**，剩余 70 张按固定顺序切四份
（14/17/17/17 及变体）。死牌顺序在开局时用本局随机源一次性生成，可复现。

> 备注：死牌山是「规则可选配置」。因为牌墙分布对剩余牌数有影响，
> 但引擎不会据此做任何策略判断，只是让局面更像实战。默认开启，可关。

## 2. 配牌与座次

- 4 人，座次 0/1/2/3。**座次 0 为庄家**。
- **连庄（renchan）**：和了者或流局时持棒者连庄。
- **不启用**四张相同牌的「配牌跳过」规则。5 张同数不合法（4 副上限）。
- **开局起手 13 张**（无 UTF 预摸），见 §17-A3。

---

## 3. 摸打流程（基本巡）

一次「巡」= 四家各摸打一次（庄家先打）。

1. 当前家从牌山摸 1 张 -> 手牌 14 张。
2. **和了判定**（若合法且非振听）-> 进入 §9 结算。
3. 非和，则从手牌中**打出一张**（含刚摸的那张）。
4. 其余三家依序对这张弃牌响应（吃/碰/杠/和/抢杠/宣言），见 §5。
5. 若无人响应，轮到下家摸牌，巡目 +1。
6. 若牌山耗尽 -> 进入 §10 流局判定。

### 3.1 巡目与局数

- 半庄（东 1-4）= 4 局 × 至多 18 巡。
- 全庄（南 1-4 或西 1-4）= 8 局。
- 亲（东家）起手 25,000 点，之子 25,000 点，总 100,000 点。

## 4. 手牌表示

- **门前（menzen）**：13/14 张暗牌。
- **副露（melded）**：见 §4.2。
- 一副和牌的形状 = **4 组面子（顺子/刻子/杠）+ 1 组雀头**，或 §6 的特殊型。

### 4.1 暗牌计数

引擎内部手牌用 **34 维计数向量** `c[34]`（0..4）表示，便于算番与去重。
另有一张牌列表用于摸打与点棒计算。两者由不变量自测保持一致。

### 4.2 副露结构

一个副露单元记为 `(kind, tile_id)`：

| kind | 说明 | 用掉手牌张数 | 暗牌移出张数 |
| --- | --- | --- | --- |
| chi 吃顺子 | 3 张，用别人打出的第 1/2/3 张 | 2 | 0 |
| pon 碰刻子 | 3 张 | 2 | 0 |
| minkan 明杠 | 4 张 | 2 | 0 |
| ankan 暗杠 | 4 张全来自暗牌 | 0 | **4** |

**组数不变量**：手牌张数 + 2×副露单元数 - (暗杠数 × 2) = 13（摸打后）。

**杠后补牌（after-kan draw）**：杠之后该家从牌山**补摸一张**，补摸后手牌 13 张，
再打出一张。杠不推进巡目。

## 5. 合法动作枚举（**这是动作空间的定义，必须逐条穷举**）

这是引擎里 `legal_actions()` 的**完整**输出。

### 5.1 轮到自己（**自摸后**）

| 动作 id | 条件 |
| --- | --- |
| DISCARD(t) | 对手牌中每一种牌各一个 |
| TSUMO | 手牌和了（14 张，合法型，非振听） |
| RIICHI | 门前、巡目 >= 4、无副露、点棒 >= 1000、且「打后听牌」 |
| RYUUKYOKU | 手牌听牌（或七对/国士听牌） |
| KAN(akan) | 手上 4 张同种牌 |
| KAN(minkan) | 手牌 3 张 + 手牌外可取得第 4 张（牌山或他人弃牌） |
| KAN(shouminkan) | **自己**副露是 pon，含 3 张同种牌，手牌外有第 4 张 |

> **注意**：吃、碰、明杠、**加杠**都是**对他家弃牌的响应**，不是自摸后的动作。

### 5.2 轮到他家弃牌（响应阶段，按弃牌者上家起逆时针顺序）

设弃牌者为 p，牌为 t。

| 动作 id | 条件 | 备注 |
| --- | --- | --- |
| RON(t) | 和了成立 + 非振听 + 非「包」 | 优先级最高 |
| CHOW(s) | **仅上家** ((p+1)%4) 可吃；t 是数牌；s 可构成顺子 | 一口吃，用掉手牌 2 张 |
| PON(t) | 手牌中有 >= 2 张 t（暗牌或副露均可） | |
| KAN(t, minkan) | 手牌中有 >= 3 张 t | |
| RYUUKYOKU | 自己听牌，可宣言流局 | |
| PASS | 上述都不做 | 总是合法 |

**响应优先级（严格按此顺序判定）**：

1. RON（含抢杠）
2. 一口吃 CHOW（同巡内先到先得）
3. KAN（加杠 -> 暗杠）
4. PON
5. RYUUKYOKU
6. PASS

若一人可吃而另一人可碰 -> **碰优先**。若两人都可碰 -> **逆时针离弃牌者最近者**。

### 5.3 座次方向

- 摸打顺序：0 -> 1 -> 2 -> 3 -> 0（逆时针）
- 「上家」= (p+1) % 4，只有上家能吃。

## 6. 和牌型（合法的 14 张形状）

### 6.1 标准型

4 组面子（顺子、刻子、杠）+ 1 组雀头（对子）。

**判定算法**：递归取「含某张牌的最小面子」优先，保证：

- 若某张牌能被顺子组成则优先顺子；
- 递归深度 <= 14，剪枝充分；
- 输出**全部**合法分解（用于番种取最高，见 §7）。

### 6.2 七对子

13 张 = 7 个对子。**门前限定**。**四个相同牌视为两对**，合法。
加杠后手牌结构变为 7 对时仍算七对子（杠不算破门）。
本规范**不实现「七对子单骑」独立番**（见 §17-A5）。

### 6.3 国士无双

1m9m 1p9p 1s9s + 东南西北白中发，全部各至少 1，共 14 张含雀头。
**必须 13 种幺九牌齐全**。本规范**不强制门前限定**（见 §17-A6b 自决项）。

### 6.4 四暗刻单骑

四组皆为暗刻（含暗杠）+ 单骑雀头。
本规范**不设「四暗刻单骑」独立役满**，单骑时按四暗刻 + 单骑处理（见 §17-A6）。

### 6.5 合法形状的完备枚举

引擎提供 `enumerate_hands(c34)`，对任意 34 维计数向量**枚举全部**合法分解。
自测 T4 用它检查：已知和了型的构造解必须被枚举器识别。

## 7. 番种与符（fu）

### 7.1 符的计算

**门前 +20 底符**。逐项叠加：

| 来源 | 符 |
| --- | --- |
| 副露（每个副露单元） | 10 |
| 门前和 | +20 |
| 雀头：场风 / 自风 / 白 / 北 | 各 +2 |
| 刻子（明刻） | 字 4 / 幺九 4 / 中张 8 |
| 暗刻 | 字 8 / 幺九 8 / 中张 16 |
| 杠（暗杠、明杠、加杠一律） | +8 |
| 单骑 | +2 |

**门前暗杠补符**：4 个暗杠里每第 1、3 个 +32（成对计 64）。

### 7.2 跳符（kuisagari）

1. 计算基础符 f。
2. 若和了为**副露**且 f <= 20 -> f = 30。
3. 若和了为**门前**且 f <= 20 -> f = 30。
4. 若 f <= 40 -> f = 40。
5. 上限 110 符。

**示例（用于实现验证）**：

| 手牌 | 符计算 | 结果符 |
| --- | --- | --- |
| 门前・20 + 幺九暗刻 8 + 白雀头 2 | 20+8+2 = 30 | 30 |
| 副露・断幺九・字暗刻 8 + 中张暗刻 16 + 雀头 0 + 副露 10 | 34 | 40 |
| 混老头・4 暗刻：字 8×4 + 中张 16×4 + 雀头 0 + 门前 20 | 20+32+64 = 116 | 110 |
| 混老头・4 明刻：字 4×4 + 中张 16×4 + 雀头 0 + 副露 10×4 | 16+64+40 = 120 | 110 |
| 七对子 | 25 符（固定） | 25 |
| 国士无双十三面 | 25 符 | 25 |

### 7.3 「符翻」硬约束

| 基准符 | 番 | 翻后符 |
| --- | --- | --- |
| 30 | 平和 / 一飜 / 七对子一飜 | 40 |

即：**符 20 或 25 的役**需再翻 10 符成 30；**符 30 的平和/一飜**再翻成 40。
符 30 的其他役（断幺九、混老头等）**不需要翻符**。
计分器把「符 30 + 平和」作为硬约束断言。

### 7.4 役（yaku）清单

**1 翻（副露可）**

```
断幺九  平和(门前)  一飜  混老头  混全带幺九  立直  一发  门前清  对对和  三暗刻
```

**2 翻**：双立直 / 七对子 / 三暗刻单骑

**3 翻**：以上之和

**跳满判定**：一组 6 翻役且和了成立 -> 跳满（8000）。
两组不同 6 翻役叠加 -> 倍满（12000）。三组 -> 三倍满（18000）。四组 -> 役满（32000）。

**役满（yakuman）**

```
国士无双十三面 = 双倍役满 64000
国士无双单骑   = 役满 32000
四暗刻单骑     = 役满 32000
小四喜         = 役满 32000
大四喜         = 双倍役满 64000
字一色         = 役满 32000
混老头（四暗刻）= 役满 32000
天和 地和 收集 四杠 大七星
```

> **自我声明**：以上役满列表在多个规则派系之间差异最大。本规范按 JPML/天凤主流
> 的数值，但**数值依据未能外部核验**（§0.1），并**标注为自决项**。
> 自测只检查「同一手牌恒定」和「点数守恒」，不检查「是否等于某个具体数值」——
> 后者需要权威表格，而本环境取不到。

### 7.5 宝牌・里宝牌・赤牌

- 牌山中下一张为**宝牌指示牌**，其**下一个数牌种**为宝牌（9 的下一张是 1）。
- 立直和了时，宝牌指示牌作为**里宝牌指示牌**置于牌山底，其下一张为里宝牌。
- **赤牌各算 1 枚宝牌**。
- 宝牌不参与和牌型判定（只翻数，不改符）。

### 7.6 符数与番的累计

**点棒 = 符 × 2^(2 + 番数)**，番数 >= 5 时停止翻倍（超过 5 翻按跳满/役满处理）。

**跳满以上（固定值）**

| 类型 | 和了方点数 |
| --- | --- |
| 跳满 | 8000 |

> **标注（自决项 A9）**：上表 3 翻 30 符取 3900/7700、4 翻取 7700/8000、
> 5 翻取 8000/12000 —— 这些是特定规则（天凤系）的取整写法，与「4 翻 = 8000」
> 的简化写法并存。本规范取前一种，但**未能外部核验**。

### 8.1 舍入与自摸的特例

- **子家和了**：父方付总数 = 基本点数 × 3（两父各付 1.5 倍基本点数，各舍入）。
- **庄家和了**：三家各付总数 = 基本点数 × 2（各 1.5 倍基本点数）。
- **跳满以上**：不做除法，直接分配。

### 8.2 包（piao）

**本规范不实现「包（责任支付）」规则**（§17-A10 自决项）。
引擎不追踪包。这不影响守恒测试，但会轻微高估放铳成本，
从而**在纯 RL 环境下引入一个系统性偏差**。已在此明确标注。

## 9. 和了流程

### 9.1 和了成立条件

1. 14 张手牌（含刚摸/刚吃的牌）为合法型（§6）。
2. 非振听（§11）。
3. 至少 1 个成立的役（§7.4）。

### 9.2 双和了（multiple ron）

**本规范支持多人同时和了**（§17-A11 自决项）：若一张弃牌能被多家和了，
则**逆时针离弃牌者最近的一家**成立，其余家不再和。

### 9.3 一发（初手）

一张弃牌同时产生「立直和了」且是**该巡第一张被打出的牌** -> 一发。

### 9.4 连庄（renchan）

- 和了者 -> 庄。
- 流局时**持棒者**连庄。
- **连庄也算「亲」**：庄家和了的三倍取点。

### 9.5 点数流转

和了方收 T 点：

| 情况 | 和了方净增 | 放铳方净减 | 其余两家净减 |
| --- | --- | --- | --- |
| 子家 放铳 和了（非跳满） | +T | -T | 0 |
| 庄家 放铳 和了（非跳满） | +2T | -2T | 0 |
| 子家 自摸（非跳满） | +T | 0 | -T/2 × 2（向下取整） |
| 庄家 自摸（非跳满） | +2T | 0 | -T/6 × 3（向下取整） |
| 逆满（8 翻） | 0 | 0 | 0 |

**点数守恒**：任何情况下「四家点数之和」在本局内保持 100,000 基准不变。
自测 T3 验证。

## 10. 流局（荒牌）

流局触发条件（满足其一）：

1. **荒牌**：巡目达上限（18 巡）且无人和了。
2. **九种九牌**：牌山剩 <= 4 张且无一家听牌。
3. **四家宣言流局**。
4. **单一宣言流局**（判断手牌已听牌：标准形听 / 七对听 / 国士听）。

**流局时点数**：

- **连棒**：+1 给持棒者。
- **供託（听牌罚符）**：听牌者每家付 300，不足 1000 时补 1000 给第一名听牌者。
- **流し満貫**：**不实现**（见 §17-A13 自决项）。

---

## 11. 振听（furiten）

某家满足以下任一，**即使和了牌型成立也不得自摸和了**（放铳和了仍可成立）：

1. **舍张振听**：自己的牌河里**已出现过**自己待的那张和了牌。
2. **同巡振听**：本巡内已经放过牌，且待牌和放过的是同一张。

## 12. 合法动作的边界情况（逐条实现）

### 12.1 可碰不可碰

- 手里已有 **4 张相同牌**（该牌 4 副已尽）-> 不可碰。
- **副露已达 4 组** -> 不可碰（4 组 + 雀头 = 5 组，超和牌型）。
- 场上已有人碰过该牌 -> 自己仍有第 4 张时可再碰（4 副共 16 张，规则允许）。

### 12.2 抢杠（chankan）

- 对手**加杠**时，若该牌被抢和且不是振听 -> **加杠失败**，改由和了方收牌结算。
- 抢杠和了按**明和**结算（不享受门前 +20）。
- 引擎在加杠时把所有合法 ron 都枚举出来。

### 12.3 抢暗杠

暗杠**不可被抢**。本规范不实现抢暗杠。

### 12.4 立直限制

- 必须**门前**。
- 巡目 >= 4（西 1 起）才允许立直。**不实现「1 巡闷立直」**（见 §17-A14）。
- 点棒 >= 1000（不足则减到 0）。
- 立直宣告后**必须打出一张**，且此后**只能摸打**（不能吃碰杠），摸到必须打。

### 12.5 吃牌限制

- 只有**上家**能吃。
- **字牌不能吃**。
- **门前清不可吃**。立直后不能吃。
- 吃满 4 组后不可再吃（除非已和）。

### 12.6 杠牌限制

- **暗杠**：手上 4 张同种牌。
- **明杠**：手牌 3 张 + 牌山或他人弃牌的第 4 张。
- **加杠**：自己副露是 pon，且牌山/弃牌出现第 4 张。
- 杠后**从牌山补摸一张**，暗杠补摸仍不破门，番数不减。

### 12.7 九种九牌

牌山剩 <= 4 张时进入流局检查；无人和了 -> 流局。听牌者按罚符结算。

## 13. 终止条件

| 终止 | 条件 | 结果 |
| --- | --- | --- |
| **和了** | §9 全部满足 | 点数按 §9.5 结算 |
| **流局** | §10 任一 | 点数按 §10 结算 |
| **点数终止（tobi）** | 某人点数 < 0 | 本局结束，按位次结算 |

**注**：本规范**不把「单局点数为负」判为终局**（允许负债），
只在整场结束时按位次结算。

### 13.1 终局点数

- 半庄结束（东 4 后）：按位次 + 1000/3000/5000/7000。
- 全庄结束：按位次 + 15000/5000/-5000/-15000。
- **位次定序**：点数降序，同点按坐席序（东家起逆时针近者优先）。

## 15. 「不许基于牌效」的边界（再强调）

引擎里**禁止出现**：

- 听牌数 / 和牌率 / 进张数表
- 「某张牌打出的期望点数」
- 任何形如「安全牌」「危险牌」的标记
- 任何形如「立直更好 / 副露更好」的权重

**允许出现**：

- 「这张牌现在打出去合不合法」
- 「和了这手算多少点」
- 「这个状态是否振听 / 是否终局」

判别式（可执行）：**引擎不依赖「牌张」的相关性做决策，只依赖「合法性和点数」。**

## 18. 交叉核对状态（诚实标注）

**已外部核验**：无。本环境网络受限（§0.1），无法访问权威规则库。
**可执行核验**：§16 的 T1-T8 自测，全部为**内部一致性**检查。

**必须说清的一句话**：T1-T3 证明的是**引擎自洽**（牌不丢、点不漏、和了合法），
**不证明**「这手牌值 3900 而非 4000 是对的」。后者需要权威规则表交叉核对，
本环境做不到。这一点不掩饰。
