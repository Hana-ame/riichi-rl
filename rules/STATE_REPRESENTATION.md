## 0. 铁律：不许作弊的观测（对应用户铁律「观测不能超过玩家真实可见」）

### 0.1 进观测的信息（全部是公开或自有的）

| 信息 | 理由 |
| --- | --- |
| 自己的暗牌计数 | 自己的牌当然可见 |
| 四家的牌河 | 打出来的牌全桌可见 |
| 四家的副露 | 副露全桌可见 |
| 宝牌指示牌 | 立在牌山上可见 |
| 里宝牌指示牌 | 立直后可见（未立直时该位恒为 0） |
| 各家点数 | 公开计分器 |
| 巡目、场风、自风、庄家身份 | 公开 |
| 各家剩余手牌张数 | 公开（副露数决定，打牌数决定） |
| 牌山剩余张数 | 公开 |
| 自己/各家的振听标志 | 见 §0.3 的说明 |
| 阶段（摸打 / 响应） | 公开 |

### 0.2 明确**不**进观测的信息

| 不给的东西 | 理由 |
| --- | --- |
| 对手手牌（任何形式） | 真实对局看不到 |
| 牌山顺序 / 未来牌 | 真实对局看不到 |
| 「对手听没听牌」的精确标记 | 振听是**推断**出来的，不是标记 |
| 任何听牌数 / 和牌率 / 安全牌 | 见 §0.4 |

### 0.3 关于振听标志的取舍

观测里给了**自己的**振听标志（`p.furiten`）。这是引擎按规则算出来的，
不是从牌河反推的策略量。它等价于「玩家自己知道自己在振听」
（真实对局里玩家确实能确定这一点）。

**没有**给对手的振听标志，因为那需要额外推断，属于策略信息。

### 0.4 「不进观测」的运行时检查

`selftest.py` 之外，我建议加一条**结构性检查**作为交付末尾的可执行判据：
把 `encode_observation` 的输入参数收窄成「只允许传公开信息」，
在类型层面杜绝把对手手牌塞进去。当前实现里 `encode_observation(env, p_idx)`
只从 `env.players[p_idx]` 取自己手牌，其余全部走公开字段，
可审计。

## 1. 观测编码（实现：obs.encode_observation）

定长 float 向量，**长度 436**（`obs.OBS_DIM`）。

| 段 | 维度 | 内容 |
| --- | --- | --- |
| 1 | 34 | 自己手牌计数（0..4） |
| 2 | 136 | 四家牌河计数（4 × 34） |
| 3 | 136 | 四家副露计数（4 × 34） |
| 4 | 4 | 各家副露组数 |
| 5 | 4 | 各家点数（归一化并截断到 [-1,1]） |
| 6 | 1 | 自己是否庄家 |
| 7 | 1 | 巡目 / 18 |
| 8 | 4 | 场风 one-hot |
| 9 | 4 | 自风 one-hot |
| 10 | 34 | 宝牌指示牌 one-hot |
| 11 | 34 | 里宝牌指示牌 one-hot |
| 12 | 1 | 自己振听 |
| 13 | 1 | 自己立直 |
| 14 | 1 | 牌山剩余 / 70 |
| 15 | 4 | 各家手牌张数 / 14 |
| 16 | 35 | 上一张弃牌存在标志 + one-hot |
| 17 | 2 | 阶段 one-hot（摸打 / 响应） |
| | **436** | |

**编码方式说明**：
- 计数用原始张数（1m 手里有 3 张就是 3.0），不是归一化。
  归一化交给网络第一层。
- 点数做线性缩放 + 截断，因为点数可以变负（负债）且跨局累计。
- 阶段 one-hot 让网络知道「现在该我打牌」还是「该我响应」——
  这两者动作空间完全不同（见 §2）。

### 1.1 编码的已知取舍（诚实标注）

- **点数是绝对值而非相对值**。相对值（自己减平均）可能更适合学习，
  但绝对值保留了「我离破产有多远」的信息。当前选绝对值 + 归一化。
- **没有把「自己副露了几组、能否平和」直接给特征**。
  这些是能从副露计数推出来的派生量，给不给是设计选择，不是信息泄漏。
- **没有牌山剩余牌的构成**（只知道张数，不知道是哪几种）。
  真实对局里玩家能看到自己牌山末尾的牌，但那是「看牌」行为，
  不属于默认观测；作为扩展可以加，本版本不加。

## 2. 动作空间

### 2.1 动作枚举（对应 RULES.md §5）

动作类型（`env.py` 常量）：

| 动作 | 参数 | 出现阶段 |
| --- | --- | --- |
| DISCARD | tile（34 种） | 摸打 |
| TSUMO | — | 摸打 |
| RIICHI | tile（宣告后立即打出的那张） | 摸打 |
| ANKAN | tile | 摸打 |
| MINKAN | tile | 响应 |
| CHI | (起始牌, 被吃的牌) | 响应 |
| PON | tile | 响应 |
| ADD_KAN | tile | 响应 |
| RON | tile | 响应 |
| RYUUKYOKU | — | 两者皆可 |
| NAGASHI | — | 两者皆可 |
| PASS | — | 响应 |

### 2.2 定长槽位映射（因为动作数不定长）

固定槽位空间大小 `ACTION_SPACE_SIZE = 34 + 20 = 54`：

- **槽位 0..33**：直接对应「打出 tile t」。
- **槽位 34..53**：特殊动作，用稳定哈希
  `slot = 34 + (type*1000003 + tile*101 + arg) % 20`。

**冲突处理**：同一槽位被多个动作抢占时，取 `legal_actions()` 列表里
靠前的一个，其余动作**在掩码里不可见**。

> ⚠️ **这是一个已知的表示损失，必须说明**：
> 如果两个合法动作哈希到同一槽位，策略无法区分它们。
> 实测冲突概率低，但**没有做无冲突保证**。
> 这是「定长动作空间」的固有代价。
> 替代方案是用「分解动作头」（先选动作类型，再选牌），
> 但那会改变网络结构，属于第二阶段的事。

### 2.3 非法动作的处理

三条防线：

1. **掩码**：`legal_action_mask()` 只把合法动作对应的槽位置 1。
2. **裁决**：引擎对不合法的提交做兜底（例：打牌时牌不在手里，
   回退到打摸到的那张）。
3. **自测**：T1/T2 逐步检查牌数守恒与和了合法性，
   兜底路径若产生牌数异常会被立刻抓到。

**策略侧应当用掩码做 masked softmax**，非法动作概率为 0。
若策略仍采样到非法动作，引擎兜底 + 自测报警。

### 2.4 多主体同一步

一步里可能有多个主体各自决策（响应阶段 3 家），
引擎按 RULES.md §5.2 的优先级裁决。
**被驳回的动作不算错误**，引擎把它标记为 rejected，不惩罚策略。
理由：响应阶段的优先级是规则，不是策略的选择；
让策略为「规则优先级」负责会把规则信号混进策略梯度。

## 3. 终局判定

| 终局 | 触发 | 结果对象 |
| --- | --- | --- |
| `tsumo` | 自摸和了（牌型 + 有役 + 非振听） | GameResult(delta, scores, yaku) |
| `ron` | 放铳和了 | 同上 |
| `ryuukyoku` | 荒牌 / 九种九牌 / 宣言流局 / 牌山耗尽 | delta 来自听牌罚符 |
| （未实现） | tobi / 位次结算 | 见 RULES.md §13 |

**一局 = 一个 GameResult**，不含连庄（连庄属于「半场」层面，
第二阶段做多局连庄时再加）。当前 env 一局即终局，
`GameResult.scores` 给出结算后点数，可直接进 RL 奖励。

## 4. 可复现性

- `MahjongEnv(seed)` 用 `random.Random(seed)` 单一随机源。
- 洗牌、每一张弃牌的随机选择都走这个源（策略侧的选择不进引擎随机源）。
- 自测 T8 验证：同 seed → 同步数、同结果、同点数变化。

**并行**：引擎无全局状态，`MahjongEnv` 实例之间互不干扰，
可以直接多进程跑（每进程不同 seed 段）。这一点在第二阶段做批量采样时用。

## 5. 与「不许牌效」的边界复核

观测里给的每一项都能回答「局面是什么」，
没有一项能直接回答「该打哪张」。

- 牌河计数 + 副露 + 剩余张数 -> 网络可以自己学出「安全牌」，
  但那是**网络从数据里学的**，不是引擎喂的。
- 引擎的 `_is_tenpai` 只用于「能否立直 / 能否宣言流局」的合法性，
  **不会**进入观测，也不会影响动作合法性以外的任何东西。

> 可执行的验证方式：把 `obs.encode_observation` 的输出打印出来，
> 人眼扫一遍，确认没有任何一位是「和牌数」「期望值」之类的量。
> 当前所有字段都能在 RULES.md 里找到对应的规则定义。
