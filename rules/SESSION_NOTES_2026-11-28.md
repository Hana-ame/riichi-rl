## 补记：跨版本 Elo 对比的两大陷阱（2026-11-28 深挖）

### 陷阱一：把不同配置的 arena 当 before/after 对照
修复前旧数据(ELO_all_with_destprob_600.md) = arena_elo.py / 600局 / 10-11人 / 带选员淘汰
我跑的修复后数据(ELO_fixed.md) = arena_fixed_elo.py / 300局 / 9人固定 / 无淘汰
四处不一致(局数/seed/阵容/淘汰机制)，不构成有效 before/after。
**结论：eff_wuke_d2「1822→1537 退化285分」的说法作废，不可引用。**

### 陷阱二：误以为 _rule_override 影响所有策略
_rule_override 只在 V1Agent/HanchanAgent/BCAgent(M **L** Agent) 调用；
RuleAgent.act 直接走 pol.choose，**不经过 _rule_override**。
- damaten/pure_shanten/dest_prob_v3/greedy_tenpai/riichi_needed/riichi_ev 全是规则策略
  → 从不受 _rule_override 管 → 修复它对这些策略行为零影响
- 真正受影响的是 eff_wuke_d2/teacher47_*/tenhou_bc 等 **ML Agent**
  → 修复后 ML Agent 的立直决策才真正交给网络(不再被强制立直)

**推论**：修复后 pure_shanten 升到第2 / damaten 掉到末位，
都不能归因于"立直放开"，只能是 Elo 零和 + 阵容/局数/seed 差异 + 策略本性组合。
规则策略之间没有"谁被 bug 扭曲"的差别。

### 方法论
- 跨版本比较必须固定 局数/seed/阵容/规则版本 四要素，否则无效
- Elo 排名 ≠ 和牌率 ≠ 打点(pt)：pure_shanten 排名第2但和牌率仅9.1%靠防守生存
- 一次 arena 的排名变化有大量方差，单 seed 不可当结论

## 补记9：修复效果在 Elo 层面不可检测（定量估算）

### 样本量估算
观察 seed16000 vs seed22000 第一名差 270 分 → 单 arena Elo sigma ≈ 135 分。

要检测 ±25 分的真实修复效果（90% 置信）：
- 需要 n ≈ 229 个独立 arena × 300 局 = **约 68,500 局**
- 这在计算上完全不现实

### 各修复对实战的真实影响
| 修复 | 对实战影响 | 原因 |
|---|---|---|
| shanten 委托 | **零** | mahjong/shanten.py 是死代码，实战走 refengine |
| reselect 保证 | **零** | arena_fixed_elo 固定 9 人池，不走 reselect |
| 食替禁止 | 极小 | 只在碰后当巡切同牌的罕见情形 |
| 庄家倍数 1.5 | 小-中 | 只在庄家荣和时（约 1/4 对局 × 荣和率） |
| 立直放开 | 中 | 只影响 ML Agent（eff_wuke_d2/teacher47/tenhou_bc） |

### 最终定论
**修复在代码层面是正确的（单元测试 5/5 PASS），但 Elo 排名无法检测其效果**：
- 单 arena 的 Elo sigma（≈135）>> 修复效果（≈几个分）
- 300 局 × N 个 arena 仍需 N > 200 才能检测
- **这不是修复失败，而是修复的效果天然小于随机方差**

### 修复的价值重估
修复的价值不在 Elo 排名，而在**代码正确性**：
1. shanten 清理：消除误导性死代码，避免未来误用
2. 结算正确性：庄家 1.5 倍、跳满梯度——单独对局内正确
3. 立直放开：ML Agent 获得默听自由（策略空间扩展）
4. 食替禁止：规则合规
5. reselect：修复潜在边界 bug

**这些修复是对的，只是 Elo 排名这个指标太粗，测不出它们的价值。**

  （某玩家手牌 8/5/7 张，刚碰杠未补牌），是**正常边界**，非脏值

### 所以 win_prob AUC≈0.5 的真实原因
**不是数据污染，而是任务本身极难**：和牌概率受对手策略、牌山、防守多方影响，
单靠 34 维手牌 + 几个标量特征本就难以预测。AUC≈0.5 说明这个预测头需要更强的
特征（对手手牌/牌河序列），而不是修 shanten 能解决的。

**结论：③（和牌率预测）是「特征/模型能力不足」，不是「数据被 bug 污染」，
修 shanten 对它零帮助。这条线在修复包应用后无需重测。**

## 补记11：本轮方法论总纲（评估修复效果的正确姿势）

### 核心矛盾
5 个 bug 修复在代码层面全部正确（5/5 单元测试 PASS），但 Elo 排名验证不出来——
因为修复效果（±20 分）被 seed 随机性（±270 分）完全掩盖。

### 三个层次的验证手段

| 层次 | 手段 | 能否验证修复 |
|---|---|---|
| 单元测试 | 直接调用函数，喂边界输入 | ✅ **最强**——shanten/结算/食替/reselect 都在此层 PASS |
| 单 seed Elo | 跑 300 局看排名 | ❌ **无效**——seed 方差 ±270 >> 修复效果 ±20 |
| 多 seed Elo | 跑 5+ seed 取平均 | ⚠️ 理论可行但需 ~68500 局，不现实 |

### 结论：不同修复需要不同的验证手段

| 修复 | 正确验证方式 | Elo 能否检测 |
|---|---|---|
| shanten 公式 | 单元测试喂边界手牌 | ❌（死代码，实战无影响） |
| 结算（庄家倍数/番数） | 单元测试喂特定手牌 | ⚠️ 稀疏（大番罕见） |
| 食替禁止 | 单元测试构造碰后场景 | ❌（极罕见） |
| 立直放开 | 行为测试（模型能否选默听） | ⚠️ 只影响 ML Agent |
| reselect | 单元测试（池含后半部分） | ❌（fixed_elo 不走此路径） |

### 最终判断
**本轮 5 个修复全部在单元测试层 PASS，这是它们能给出的最强证据。**
Elo 排名变化无法作为修复有效性的判据——不是因为修复无效，
而是因为修复解决的是**具体手牌的正确性**（如庄家该 12000 不该 24000），
这类正确性在 300 局平均后就被稀释到方差以下了。

**修复的价值 = 代码正确性，不是 Elo 分数变化。**

## 补记12：②和牌率预测「不可行」的根因定论（base_win 失衡）

### 核心数据
- `hand_predictor.pt` 元数据：base_win = 0.946%（训练时和牌率）
- 真实 arena 和牌率：32-41%（eff_wuke_d2 / dest_prob_v3）
- **训练/实战 base rate 差 40 倍**

### 根因
`hand_predictor` 训练数据来自 `data/selfplay/`（703 局 greedy_tenpai 自对弈）。
greedy_tenpai 是「能听牌就听、能立直就立直、其余弃和」的策略，
在 4×greedy 同桌下**几乎不和牌**（和牌率 <1%），所以：
- 正样本（和牌）占比 <1%，99% 是负样本
- 任何分类器在这种极端不平衡下都会退化成「全预测不和牌」
- AUC≈0.5 不是模型差，是**任务在 greedy 环境里没有可学习信号**

### 为什么修 shanten 不能救它
shanten 特征本身是正确的（走 refengine）。问题不在特征错，
而在**训练分布（greedy 自对弈）和实战分布（真实攻防）严重不匹配**。
即使 shanten 特征正确，greedy 环境里「这个决策点最终会不会和牌」
的答案几乎总是「不会」，模型学不到任何区分性模式。

### ②的唯一可行路径
**②-B：必须在真实攻防环境（非 greedy 自对弈）重新采集 win 标签**
- 数据源：eff_wuke_d2 / dest_prob_v3 自对弈（这些有 32-41% 和牌率）
- 而非 greedy_tenpai 自对弈（<1% 和牌率）
- 采集成本：需先跑足够多的真实对局（非 30 局 smoke）

### 结论
②的低 AUC **不是 bug，是训练数据分布错误**。
修复包（shanten/结算）对这个任务零帮助。
要做 ②，需先解决「在哪个环境采集 win 标签」这个数据源问题。
