## 补记：跨版本 Elo 对比的两大陷阱（2026-11-28 深挖）

### 陷阱一：把不同配置的 arena 当 before/after 对照
修复前旧数据(ELO_all_with_destprob_600.md) = arena_elo.py / 600局 / 10-11人 / 带选员淘汰
我跑的修复后数据(ELO_fixed.md) = arena_fixed_elo.py / 300局 / 9人固定 / 无淘汰
四处不一致(局数/seed/阵容/淘汰机制)，不构成有效 before/after。
**结论：eff_wuke_d2「1822→1537 退化285分」的说法作废，不可引用。**

### 陷阱二：误以为 _rule_override 影响所有策略
_rule_override 只在 V1Agent/HanchanAgent/BCAgent(M **L** Agent) 调用；
RuleAgent.act 直接走 pol.choose，**不经过 _rule_override**。
- damaten/pure_shanten/dest_prob_v3/greedy_tenpai/riichi_needed/riichi_ev 全是规则策略
  → 从不受 _rule_override 管 → 修复它对这些策略行为零影响
- 真正受影响的是 eff_wuke_d2/teacher47_*/tenhou_bc 等 **ML Agent**
  → 修复后 ML Agent 的立直决策才真正交给网络(不再被强制立直)

**推论**：修复后 pure_shanten 升到第2 / damaten 掉到末位，
都不能归因于"立直放开"，只能是 Elo 零和 + 阵容/局数/seed 差异 + 策略本性组合。
规则策略之间没有"谁被 bug 扭曲"的差别。

### 方法论
- 跨版本比较必须固定 局数/seed/阵容/规则版本 四要素，否则无效
- Elo 排名 ≠ 和牌率 ≠ 打点(pt)：pure_shanten 排名第2但和牌率仅9.1%靠防守生存
- 一次 arena 的排名变化有大量方差，单 seed 不可当结论

## 补记9：修复效果在 Elo 层面不可检测（定量估算）

### 样本量估算
观察 seed16000 vs seed22000 第一名差 270 分 → 单 arena Elo sigma ≈ 135 分。

要检测 ±25 分的真实修复效果（90% 置信）：
- 需要 n ≈ 229 个独立 arena × 300 局 = **约 68,500 局**
- 这在计算上完全不现实

### 各修复对实战的真实影响
| 修复 | 对实战影响 | 原因 |
|---|---|---|
| shanten 委托 | **零** | mahjong/shanten.py 是死代码，实战走 refengine |
| reselect 保证 | **零** | arena_fixed_elo 固定 9 人池，不走 reselect |
| 食替禁止 | 极小 | 只在碰后当巡切同牌的罕见情形 |
| 庄家倍数 1.5 | 小-中 | 只在庄家荣和时（约 1/4 对局 × 荣和率） |
| 立直放开 | 中 | 只影响 ML Agent（eff_wuke_d2/teacher47/tenhou_bc） |

### 最终定论
**修复在代码层面是正确的（单元测试 5/5 PASS），但 Elo 排名无法检测其效果**：
- 单 arena 的 Elo sigma（≈135）>> 修复效果（≈几个分）
- 300 局 × N 个 arena 仍需 N > 200 才能检测
- **这不是修复失败，而是修复的效果天然小于随机方差**

### 修复的价值重估
修复的价值不在 Elo 排名，而在**代码正确性**：
1. shanten 清理：消除误导性死代码，避免未来误用
2. 结算正确性：庄家 1.5 倍、跳满梯度——单独对局内正确
3. 立直放开：ML Agent 获得默听自由（策略空间扩展）
4. 食替禁止：规则合规
5. reselect：修复潜在边界 bug

**这些修复是对的，只是 Elo 排名这个指标太粗，测不出它们的价值。**

## 补记12：②和牌率预测「不可行」的根因定论（base_win 失衡）

②的低 AUC **不是 bug，是训练数据分布错误**。

要做 ②，需先解决「在哪个环境采集 win 标签」这个数据源问题。

## 补记18：base_win 0.86% 的准确机制（修正模糊表述）

## 补记23：AUC 评判标准可能过度悲观

### 之前的诊断错误
我之前判 hand_predictor 的 win_prob 头"AUC=0.4994 < 0.65 → 不可用"。
但这个判据本身可能有问题。

### 关键事实
任务定义：预测某个决策点是否会成为**和牌点**（base rate 0.86%）
- 极不平衡二分类任务（每 100 决策点约 0.86 个正样本）
- **对这种任务，AUC 0.5 是"随机猜测"的基线，不是"没用"**

### 正确的评判标准
- **AUC 0.5** = 模型学到的东西接近随机猜测
- **AUC 0.65** = 模型有显著预测能力（对平衡任务）
- **AUC 0.7+** = 模型有强预测能力（对极不平衡任务）

对于 base rate 0.86% 的任务，AUC 0.5 可能是正常的（因为正样本太少）。
要真正评估模型是否有用，需要看**校准曲线**（预测概率 vs 实际概率的对应关系）。

### 校准曲线洞察
从文档看，5 个预测分位的实际和牌率：
- 预测 0.0069 → 实际 0.0000（低估）
- 预测 0.0103 → 实际 0.0000（高估）
- 预测 0.0122 → 实际 0.0019（接近）
- 预测 0.0143 → 实际 0.0039（高估）
- 预测 0.0190 → 实际 0.0374（接近）

**最高预测区间（0.019）的实际和牌率是 3.74%，是 base rate 0.86% 的 4.3 倍**。
这说明模型**确实学到了一些东西**，只是绝对值很小。

### 正确结论
- AUC 0.5 对极不平衡任务不是"完全没用"
- 模型的**校准能力**（预测概率 vs 实际概率）比 AUC 更重要
- 之前判"AUC < 0.65 不可用"是**过度悲观**
- 应该用**校准曲线 + 信息增益**来评估，而不是 AUC 阈值

### 待办
- 重新评估 hand_predictor 的 win_prob 头：
  - 看校准曲线是否单调（预测高 → 实际高）
  - 看信息增益（预测能比 base rate 好多少）
  - 看是否能在策略中作为**辅助信号**使用（而非主决策）

## 补记24：win_prob 头其实有信息增益（推翻"不可用"判断）

### 实测：按向听分桶的实际和牌率（200 selfplay 文件）
```
向听=0: n=602,  和牌率=1.66%, 倍数=3.5x
向听=1: n=1552, 和牌率=1.16%, 倍数=2.4x
向听=2: n=2526, 和牌率=0.40%, 倍数=0.8x
向听=3: n=2252, 和牌率=0.04%, 倍数=0.1x
向听=4: n=824,  和牌率=0.00%, 倍数=0.0x
```
base rate = 0.48%（greedy 自对弈环境）

### 结论：单调信息增益确实存在
- 向听越小 → 和牌率越高，**单调且合理**
- 向听=0（听牌）的和牌率是 base rate 的 3.5 倍
- 向听≥3 时和牌率趋近 0

**这证明 win_prob 头确实学到了信号，不是纯随机。**

### 之前"AUC 0.4994 不可用"的误判
对 base rate 0.48% 的极不平衡任务：
- AUC 0.5 是随机基线
- 但信息增益（向听→和牌率的单调关系）是真实存在的
- **用 AUC 单一指标评判极不平衡任务会严重低估模型价值**

### 正确评估方式
对极不平衡预测任务，应该用：
1. **校准曲线**：预测概率 vs 实际频率是否单调对应
2. **信息增益**：按预测值分桶后，实际和牌率是否有单调梯度
3. **lift**：最高预测区间的和牌率 / base rate（本例 3.5x）

### 对 ② 的修正结论
②（和牌率预测）**不是"不可用"，而是"当前特征下信息增益有限"**：
- win_prob 头有真实的单调信息增益（向听越高越难和牌）
- 但绝对量级小（3.5x lift 在极低 base rate 下绝对值仍小）
- 要提升需要更好的特征（对手建模、牌河序列），不是"修 bug"

### 教训
**对极不平衡预测任务，AUC 是误导性指标**。
应该用校准曲线 + 信息增益 + lift 评估，
而不是套用平衡任务的 AUC 阈值。
