## 1. 形状特征是什么（以及为什么不算牌效）

`mahjong/touch.py`，8 维：副露组数 / 刻子数 / 顺子数 / 对子数 / 孤张数 /
是否听牌 / 待牌种数 / 向听归一。

**每一维都能对任意手牌算出来**，不含「牌 A 与牌 B 的相关性」。
牌效表是相关性；这里是「我这手牌已经凑成了几组」。

> 这与 `situation.py` 同一性质：都是把局面显式化，不是把技巧喂进去。

---

## 2. 性能真相（本机）

这台机器的 GPU 是 **GTX 750 Ti / 2GB**（KB 有记），逐点前向 17.2 ms 且会 OOM，
所以全部走 CPU。实测：

| 环节 | 耗时 |
| --- | --- |
| 半庄采集（8 局） | **5.3 秒** |
| 单次前向（1200 样本） | 15.6 秒 |
| 单次反向（1200 样本） | **22.6 秒**（瓶颈） |
| 优化器一步 | 4.5 秒 |
| **每迭代（2 半庄）** | **约 70 秒** |

向量化掩码后从 80 秒/iter 降到 35 秒/iter（单半庄）。

> **注意**：后台训练会占满 6 个 CPU 线程，评估时必须先 `SIGSTOP` 暂停、
> 评估完 `SIGCONT` 恢复，否则评估会被训练饿死（我踩过一次，评估直接超时）。

## 4. 为什么还没学会（我的判断）

三条，按可能性排序：

1. **训练量远远不够**。当前 iter=15 / deals=256。参考：
   LLM_Mahjong 纯血线 **32M-64M 局**才到 share 0.4568。
   我们现在 256 局，差 5 个数量级。
2. **采样仍是均匀随机**（on-policy 分布的已知近似）。
   为了让 CPU 跑得动，我让采集阶段只做均匀采样、前向延后到训练时。
   这意味着**策略自己的分布没有被采样**，梯度信号与策略分布不一致。
   这是当前最大的近似误差。
3. **奖励仍偏稀疏**。分差项在一局里大部分时间是 0。

> **诚实的说法**：现在这套只能证明「训练链路通了、指标在动」，
> **不能证明「学到了麻将」**。判据没通过就是没通过。
