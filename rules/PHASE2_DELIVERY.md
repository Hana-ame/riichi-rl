## 2. 弃听 / 全防 / 场次 / 分差 的设计

### 2.1 与「牌效」的边界（铁律）

`mahjong/situation.py` 只输出**局势分类**，不输出「该打哪张」：

- 输入：分差、场次进度、巡目、**立直家数**（公开宣告）、自己的向听数
- 输出：normal / ahead / behind / defense / last_chance 一个标签 + 12 维特征

它不含进张数、危险牌、期望值。**这是比分板，不是麻将技巧。**

### 2.2 分类优先级（修正过一次）

```
末局搏命 > 有人立直（需防） > 大幅领先/落后 > 均势
```

原实现把「大幅领先/落后」排在「有人立直」之前，实测 **60 局里 defense=0**——
被 behind/ahead 先匹配掉了。现已修正为 defense 63 次 / last_chance 5 次。

### 2.3 弃听（放弃和了、保命）

触发条件全部是**局面算术**，不是技巧：

```
  落后额 > 剩余可争取额（每局上限 × 剩余局数）
  且 巡目 > 66%
  且 自己还没听牌
  且 不是末局搏命局
```

**听牌后不触发**（已经听牌就该搏，不是该弃）。

### 2.4 奖励（训练用，不改规则）

```
r = 1.0 × Δ分差/10000                    主目标
  + 0.5 × (向听不增)                      手牌完整性
  - 放铳惩罚 × 局势系数                   有人立直 ×2.5
  + 0.8 × (弃听局里没输钱)
```

## 3. 向听作为奖励源：实测数据（重要）

我最初的奖励是「向听下降给分」。**实测证明这是错的**：

```
1702 个 14 张决策点里，靠打牌让向听下降的次数 = 0
但 1620/1702（95.2%）存在「打出去会让向听变差」的牌
```

向听数只由手上的牌决定，**打牌不会降低它，只有摸牌才会**。
所以正确整形是「保持不上升，变差则罚」——奖励符号已修正。

对照实验（同一引擎）：

| 策略 | 和牌率 |
| --- | --- |
| 均匀随机 | 1% |
| 待牌数贪心（坏目标） | 3.5% |
| **向听贪心** | **38%** |

这证明引擎能被自然打出和牌，梯度非零。
