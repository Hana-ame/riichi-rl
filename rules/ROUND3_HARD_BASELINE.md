## 3. 三项动作空间检查（逐个证伪）

### 3.1 三个恒 0 计数器的代码路径

位置：`train_hanchan.py:262-268`

```python
for rec in info:
    label, gu = rec[6], rec[7]
    if label == "defense":      defense_seen += 1
    if label == "last_chance":  lastchance_seen += 1
    if gu:                      give_up_seen += 1
```

**证伪测试（两个方向都测了）**：

```
测试 A（随机策略下有没有人立直）：
  RIICHI 动作出现在合法集合里的次数 = 0

测试 B（人工造一个立直）：
  e.players[2].riichi = True  ->  p0 的 sit.label = defense   （计数器立刻会 +1）
```

**结论：计数器代码路径通，是上游场景未触发。**

**真正的上游原因（本轮新发现）**：训练里 `HanchanState(dealer=random)` 的
`sticks` 永远是 `[25000,25000,25000,25000]`，`hanchans=2` 意味着只有 16 局、
且**全是流局**（流局不改点数），所以：

- `point_gap` 恒为 0 -> 既不 behind 也不 ahead -> giveup / last_chance 均为 0
- 无人立直 -> defend 为 0

给足分化点数后（人工设 sticks），实测：

```
total decision steps = 7806
giveup=True   = 207 (2.65%)
last_chance   = 320 (4.10%)
```

**三个计数器都是「预期为 0」，读数本身有效。**

### 3.3 弃牌集合完整性

```

弃牌槽位: min=0 max=14 avg=2.4

拆解 avg=2.4 的来源：
  决策步按阶段: discard=1550, response=4632
  弃牌槽=0 的步: response=4632   （响应阶段本就不该有弃牌）
```

**结论：裁剪正确。**0 全部来自响应阶段，属预期。

## 5. 结论

随机策略 200 局 0 次和了，且**同环境向听贪心 11.5%**。
